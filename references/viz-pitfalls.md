# viz-pitfalls.md — 科研示意图绘图前拦截规则

产出 spec 之后、调用脚本之前，按以下清单逐条自查。**命中即主动修正 spec**；确需保留时向用户说明理由后再继续，不要带着已知问题绘制。设计理念参考 SciPilot figure-skill 的 viz_pitfalls（适配 draw.io 示意图场景）。

## P1 箭头语义混乱

- 同图使用 **>3 种箭头语义**时必须加 `legend`（脚本自动渲染图例）。
- 语义冲突（同一边同时标激活与抑制、边两端都是箭头却语义不明）→ 修正。
- 每条边必须能归入五类语义之一（activation/inhibition/translocation/association/production）或 `none`，否则用 `notes` 说明。

## P2 节点过多

- 节点数 **> 15** 且无明显层级 → 主动建议拆成两张图（机制主体 + 细节放大），或用容器分层；用户坚持合并时才保留。
- 单容器内子节点 **> 8** → 建议拆容器或精简。

## P3 容器嵌套

- 容器嵌套不超过 **2 层**；超过 → 拆图或扁平化（嵌套过深 draw.io 中难维护）。
- 容器必须有 `label`（区室名），无子节点的容器删除。

## P4 边交叉与回边

- 正交边交叉 **> 3 处** → 调整节点 `order`/`rank` 重排，或把交叉严重的边改 `curved`。
- 反馈/回环边（回到上游节点）用 `curved` + `dashed` + 标签注明，避免与普通激活边混淆。

## P5 文字溢出

- label 超节点宽度（中文按 1 字符 ≈ 0.5×fontSize 估算，宽度不足时）→ 缩小 `fontSize` 或加大节点 `w/h`。
- 节点默认 `whiteSpace=wrap` 自动换行；设了 `whiteSpace=nowrap` 时特别检查溢出。

## P6 孤立节点与悬空边

- 没有任何边连接的节点、缺 source/target 的边 → 检查是否有意，否则删除。

## P7 科研符号

- α β γ ± → ≤ ≥ ² ³ 等符号直接用 Unicode 写入 label；导出后核对无乱码（见 SKILL.md 交付前自检）。
- 斜体/上下标用 HTML：`<i>EGFR</i>`、`<sub>2</sub>`。

## P8 配色与色盲

- 相邻同层级节点避免同 fill 色；需要强调的节点用 `alt` 系 tone（默认主题已区分）。
- 投稿前做**灰度检查**：把导出 PNG 转灰度，确认相邻色块与箭头仍可区分（色盲友好）。必要时改用 `minimal` 主题。

## P9 图自解释

- 缩写（STAT3、MAPK 等）首次出现处用完整 label 或 `notes` 说明全称。
- ≥3 种箭头语义必带图例；"间接/推测/待验证"关系用 `dashed` 并在 notes 标注"推测"。
- 图要能脱离正文看懂：标题、图例、必要注释齐备。

## P10 与参考图的一致性

- 参考图/草图中存在的实体、箭头方向、分组边界必须全部入 spec（除非用户明确说忽略）。
- 图中没有的细节不猜测；无法确定的用 `dashed` + notes"推测"，不要编造成实线事实。
